# 2026-10-30 看板设计优化

使用用户确认的 design-taste-frontend 和 GSAP，改造现有 FastAPI + 原生前端。选择 Framed sheet，seed `1188424797`，保留已有 Geist 字体，未重抽。首要问题是：哪个开源项目值得继续阅读？最大的内容区仍由真实仓库介绍、README 要点与阅读入口组成。

## 数据与使用场景

- 对象是仓库，包含作者、分类、语言、简介、中文摘要和标签。
- Star 总数与最近抓取的增长是不同指标；增长排序说明其抓取基准。
- Star 历史来自既有接口，不补造数据点或每日增长率。
- 项目库现有 357 个项目，357 篇中文摘要；本次预览有 2 个收藏。
- 总量来自状态接口，结果数来自当前查询，不把分页条数当作总量。
- 收藏概况和导航数量使用同一个收藏 ID 集合。
- 读者通过浏览、搜索、分类和排序判断项目用途，再进入摘要或问答。
- 桌面用于横向比较项目；手机优先保证首条项目及阅读动作可见。
- 项目的身份来自分支标识、仓库名、作者头像及中文 README。
- 数据快照沿用真实抓取时间；较旧数据有明确的更新提示。

## 视觉与操作

采用 216px 固定导航，48px 顶部位置栏，以及右侧内缩 8px 的独立工作区。浅色框架使用 `#f2f5f8` 蓝灰色，工作区保持白色；深色使用中性黑灰。这个低饱和框架和蓝色分支标识构成产品的面孔。蓝色主要用于真实增长与阅读进度。

桌面 1440px 的宽度闭合为 `216 + 1216 + 8`；工作区内部为 `2px 边框 + 48px 留白 + 571 + 24 + 571`。标题、概况、排序栏和项目列表共用两侧边缘。卡片降低标题、正文和头像的尺寸，减少重复装饰，保持阅读、摘要与问答的位置稳定。

产品的特色元素是“阅读焦点”：综合排序首位的真实项目配两个既有 README 要点，保留完整阅读入口。“增长最快”“最近收录”可以直接切换，其他排序与语言、Star 条件放在筛选面板内。列表模式的操作固定在右侧，展开摘要占据下一整行。

平板和手机将分类及主导航收进抽屉。抽屉打开时阻止背景交互，限制键盘焦点在导航内；Escape、关闭按钮与遮罩均可关闭，关闭后恢复焦点。窗口扩大到桌面宽度会解除抽屉的交互限制。手机首条项目在约 419px 处开始，位于 844px 屏幕的上半段。

GSAP 为抽屉内部增加 200ms 的操作反馈，使用 `x`、`autoAlpha` 和 `clearProps`。原有弹窗、筛选和按钮反馈继续使用本地 GSAP；减少动态效果与缺少动画库的情形均保留原生控件行为。未添加页面入场或滚动表演。

## 左栏反馈后的调整

合并“发现项目”与“全部项目”的重复入口，移除“我的项目库”分组标签，只保留一个当前选项。分类和主导航使用同一套中性线条图标、文字起点及行距；品牌区缩小，关键词和设置并排放在底部。全量项目的数量仍沿用既有状态，集中到“发现项目”的无障碍文本中。

原导航在 1440×720、390×667、844×390 下出现内部纵向溢出，手机底部操作需要滚动才能访问。新版移除内部滚动容器：窗口高度不超过 720px 时收紧间距，600px 时分类改为两列，480px 时主导航改为三列。导航控件在测试尺寸内完整可见，关键词、设置及外部链接保留键盘访问。

专项实屏复核覆盖浅色、深色各 10 种窗口尺寸；20 种布局均无内部滚动或超出边界的控件。两种主题分别验证了分类选择、返回发现、收藏视图、设置、关键词窗口、Tab 与 Shift+Tab 焦点循环、Escape 关闭。记录及截图在 `.taste-skill/navigation/`，验收脚本为 `.tmp/design-review-20261030/navigation-qa.mjs`。
