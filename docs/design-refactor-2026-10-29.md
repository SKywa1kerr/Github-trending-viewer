# 2026-10-29 页面设计重构

## 设计方向

使用 design-taste-frontend 的应用界面流程。抽取方向为 Achromatic ledger，seed `1931130273`，未重抽。界面回答的首要问题是：这个开源项目做什么，是否值得继续阅读？

项目的身份来自真实仓库名、作者头像、中文 README、Star 记录和阅读操作。中性蓝灰底色、Geist 字体、分支标识，以及首页一个仓库的正文与 README 速览并列，构成产品的视觉语言。导航使用中性色，强调色集中在真实增长数据和阅读进度上。

## 信息与布局

- 1200px 内容列，顶部标识、主导航、搜索、筛选和项目区共用外边缘。
- 首屏采用简洁的“发现”标题，项目库和中文摘要数量直接取自状态接口，不添加样例数字。
- 首页重点项目将仓库介绍和两个真实 README 要点并排显示，直接提供阅读入口。
- 浏览视图按两列排布项目；紧凑列表保留完整操作，并将操作集中在右侧。平板和手机采用各自的布局。
- 分类保留明确文字，降低分类色和控件装饰带来的干扰。
- 收藏、推荐、GitHub 在线搜索、关注关键词、语言与 Star 筛选、排序、展开摘要和 AI 问答沿用现有功能。

## 专注阅读与动效

- 阅读窗口使用独立滚动区域、完整摘要、更清晰的正文层级、标准／大字号和固定底部操作。
- 阅读进度来自当前正文的真实滚动位置。关闭窗口恢复背景滚动，原生 dialog 保留键盘焦点管理。
- 使用本地 GSAP 3.14.2，为弹窗开关、筛选面板和按钮按下提供轻量反馈。动效仅改变 transform 与 opacity。
- 使用 GSAP matchMedia 响应系统的减少动态效果设置，切换偏好时清理按钮动效。缺少 GSAP 时，原生操作仍可使用。
- Geist 的 Latin 字体子集和 GSAP 随静态资源分发，页面不依赖外部 CDN。中文使用本地系统字体。

## 最终应用界面复核

1. **主要问题与阅读顺序**：发现页回答“这个项目做什么，是否值得继续读”，最大的区块是实际仓库介绍和 README 要点；阅读页回答“完整摘要讲了什么”；问答页回答“我对这个项目的问题”；设置页回答“界面如何显示，项目库与连接是否正常”。阅读入口直接出现在仓库旁。
2. **边缘与留白**：导航、搜索、统计和项目区共享外边缘，三种宽度无水平溢出。平板独立处理双栏介绍和单列项目；短卡片只保留与同排操作对齐的少量留白。筛选菜单没有越出屏幕。
3. **配色与身份**：界面控件使用中性色，信号色落在真实 Star 趋势、增长和阅读进度。分支标识、仓库作者和中文 README 速览在首屏可见。主题与全部强调色的正文对比度检查通过。
4. **数字与重复事实**：项目库总数、完成摘要数在首页和设置中取自同一状态值；截图中的两处总数和完成数均为 357。当前加载的 40 条是分页结果，不作为总数相加。数字使用等宽数字；Star 排序按实际值验收。增长来自抓取字段，趋势图标题明确“最近 N 次记录”，时间统一解析为 UTC。
5. **空、零与缺失**：缺失状态使用“—”，接口返回零时显示零。摘要缺失时显示明确状态并禁用展开动作；无搜索结果和加载失败保留说明与可用的清除／重试操作。收藏数对应真实收藏队列。
6. **图表与标签**：保留原有 Star 历史折线，单条系列无需重复图例，方向与无障碍标题来自真实历史值。未加入 KPI 火花线或装饰图表，首屏与滚动截图没有标签相撞。
7. **手机操作**：导航折叠，分类在自身区域横向滚动，项目单列且首条在首屏可见。阅读窗口占满屏幕，正文独立滚动，字号和底部操作始终可用。Escape 和关闭按钮恢复背景滚动与焦点，减少动态效果模式立即开关窗口。

复核中修正的重点是手机更新入口、平板筛选菜单边界、手机阅读宽度及设置标签挤压。仍有边界：真实模型问答和 GitHub 在线请求未使用账户凭据实测，界面分别使用流式与空结果 fixture；长项目列表仍需要滚动浏览。

没有引入占位项目、虚构数据或外部图库。真实 GitHub 作者头像沿用原有加载逻辑。
